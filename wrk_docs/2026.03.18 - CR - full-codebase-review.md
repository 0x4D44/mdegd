### HIGH — Should fix before Saturday

#### H1. Ruth can see "Not quite!" on 98 questions despite guaranteed 12/12

**File:** `index.html:567-574`, `src/quiz-engine.js:82-91`

Ruth's score is force-overridden to 12/12 on the results screen (`index.html:616-618`), but during gameplay, `checkAnswer()` evaluates her answers honestly. Of 432 questions:

- 13 have all 4 Ruth options identical (always correct)
- 321 have 2+ options matching the correct text (usually correct)
- **98 have all 4 options different** (Ruth can genuinely pick wrong)

When Ruth picks wrong on those 98, she sees a red "Not quite!" verdict with the correct answer highlighted. Then at the end: "12/12 — flawless!" This is jarring.

**Options:**
1. Make all Ruth questions have identical first-two options (pattern was broken for 124 questions)
2. Override `checkAnswer` feedback in Ruth mode — always show "Correct!" regardless
3. Accept the inconsistency (it's funny if she notices)

#### H2. Welcome screen text is inaccurate

**File:** `index.html:483-484`

> "Every question is about something that happened on **your birthday — March 21st**."

Only 57 of 432 questions (13%) are about March 21st. The quiz now covers Doric dialect, Forfar Bridies, Vauxhall Cavaliers, teenage slang, etc. This will confuse players.

**Fix:** Change to something like:
> "432 questions about things Eric cares about — from March 21st history to Scottish Hydro, Doric dialect, and beyond."

#### H3. `node_modules/` is not in `.gitignore`

**File:** `.gitignore`

The `.gitignore` lists `target/`, `bin/`, `obj/`, `venv/` etc. but not `node_modules/`. Git status already shows `?? node_modules/` as untracked. One careless `git add .` would commit ~220 packages.

**Fix:** Add `node_modules/` to `.gitignore`.

### MEDIUM — Worth fixing but won't block the birthday

#### M1. `selectBalancedQuestions` is imported but never called (dead import)

**File:** `index.html:383`

After switching to `selectQuestions()` for pure-random selection, the `selectBalancedQuestions` import remains unused. Not harmful, but it's dead code.

**Fix:** Remove from the import statement.

#### M2. `selectBalancedQuestions` is still exported and tested but no longer used by the app

**File:** `src/quiz-engine.js:29-69`, `tests/quiz-engine.test.js:93-138`

The function and its tests remain. The tests still use the old category names (`us-state-history`, `us-states-attributes`, `general`) which no longer exist in the question pool. Not a bug (mock data), but the test names are misleading.

**Recommendation:** Either remove the function and tests, or update the test mock categories to match reality. Low priority — it doesn't break anything.

#### M3. No XSS protection on `innerHTML` rendering

**File:** `index.html:475, 520, 585, 623` (all `innerHTML =` assignments)

Question text, options, and explanations are injected directly via `innerHTML`. Currently safe because all content is hardcoded in `questions.js` (no user input, no API calls). But if someone ever adds dynamic content or user-submitted questions, this becomes an XSS vector.

**Current risk:** Zero (all content is author-controlled).
**Future risk:** Medium. The pattern `innerHTML = template with ${q.question}` would be dangerous with untrusted input.

**Verified:** All 432 questions were scanned — zero HTML tags, zero script content, zero event handlers in any text field.

#### M4. `questions.js` is 399 KB unminified

**File:** `src/questions.js` (399.3 KB)

Loaded raw via ES module import with no build step, no minification, no compression. On GitHub Pages with default gzip, this is probably ~80-100 KB compressed — acceptable for a one-off party quiz. But it's worth noting.

**Recommendation:** No action needed for the birthday. If the quiz grows further, consider a build step with Vite.

#### M5. Duplicate test for category validity

**File:** `tests/questions.test.js:42-46` and `tests/questions.test.js:72-78`

Two tests check category validity:
- `"all categories are valid"` (line 42) — checks against VALID_CATEGORIES whitelist
- `"all questions have a valid category"` (line 72) — checks non-empty string and counts >= 1

These overlap. The first is stricter (whitelist check). The second adds little value.

**Fix:** Remove the second test or merge them.

### LOW — Nice-to-have improvements

#### L1. No `prefers-reduced-motion` support

**File:** `index.html:283-297` (animations: `card-reveal`, `fadeIn`, `pulse`, `birthday-shimmer`)

Four CSS animations run unconditionally. Users with motion sensitivity preferences (`prefers-reduced-motion: reduce`) won't get relief.

**Fix:** Add a media query:
```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation-duration: 0.01ms !important; }
}
```

#### L2. No ARIA attributes

**File:** `index.html` (entire document)

No `role`, `aria-label`, `aria-live`, or `aria-describedby` attributes anywhere. The quiz is functional with keyboard navigation (buttons are focusable, `focus-visible` is styled), but screen readers get no structural cues.

**Key gaps:**
- Progress bar has no `role="progressbar"` or `aria-valuenow`
- Quiz card has no `role="region"` or `aria-label`
- No `aria-live="polite"` on the feedback region for announcing correct/incorrect

**Priority:** Low for a birthday party quiz, but worth noting.

#### L3. Theme-specific font stacks may not render identically cross-platform

**File:** `src/styles.js` (various `--font-heading` / `--font-body` values)

Fonts like `'Impact'`, `'Comic Sans MS'`, `'Trebuchet MS'`, `'Palatino Linotype'` are Windows-centric. macOS/Linux/mobile users may get fallback fonts that change the visual character of themes.

**Impact:** Cosmetic only. The fallback chain (`serif`, `sans-serif`, `monospace`) is always specified.

#### L4. `getResultMessage` percentage thresholds don't match score display

**File:** `src/quiz-engine.js:106-133`

The result message is based on percentage: 100, >=75, >=50, <50. But the bonus point can push Eric to 13/12 (108%). The message function receives the pre-bonus `scoreObj`, so 12/12 shows the 100% message while the display shows 13/12*. This is probably intentional humor, but the logic flow is non-obvious.

#### L5. `getCategoryDistribution` is exported and tested but never called

**File:** `src/quiz-engine.js:138-144`, `tests/quiz-engine.test.js:273-288`

A utility function that counts questions per category. It's tested but never used by the app. Possibly useful for debugging.

**Recommendation:** Keep it (zero cost, useful for ad-hoc verification).

#### L6. `year` field is missing from some questions that reference specific years

**File:** `src/questions.js` (various)

Many questions reference specific years in their text but have `year: null`. This means the year badge pill won't appear for those questions. Scan found 0 violations of the reverse (year in text but null in field), so the current state is actually consistent — checked and clean.

### OBSERVATIONS (not issues, just notes)

#### O1. Architecture is intentionally minimal — and that's correct

No framework, no build step, no state management library, no router. For a single-purpose party quiz, this is exactly the right level of complexity. The code is readable by anyone who knows HTML/CSS/JS.

#### O2. Test coverage is strong for the surface area

53 tests cover:
- All exported functions in `quiz-engine.js` including edge cases
- All 10 themes with property validation
- All 432 questions with structural validation
- DOM manipulation (applyStyle via jsdom)

The main untested area is the `index.html` inline script (DOM orchestration, event handlers, state management). This is reasonable — integration testing a single inline script adds complexity for little value.

#### O3. The `checkAnswer` text-matching design is clever

```js
correct: selectedIndex === modeData.correct || selectedText === correctText
```

This handles Ruth's "all options are the same" pattern elegantly. If all options say "Potato!", any selection matches. It also handles shuffled options where the correct text moves to a different index. The tests verify this explicitly.

#### O4. Theme quality is high

All 10 themes define the full 14-variable contract. Each has distinctive `extraCSS` with background patterns, text effects, and card decorations. The `data-theme` selector pattern avoids CSS specificity wars. The retro-computing theme (`C:\\BIRTHDAY\\QUIZ.EXE`) is particularly good.

#### O5. Question pool is enormous for a 12-question quiz

432 questions with 12 per game means ~36 completely unique playthroughs before any question repeats. The question quality is high — explanations are detailed, options are plausible, and the personal/insider questions (NSHEB, family jokes, Eric's suitcase) add genuine warmth.
